# Полёт сквозь Вселенную

Одностраничный сайт со scroll-driven 3D-анимацией: камера летит от Земли через Солнечную систему к
чёрной дыре Стрелец A*, Млечному Пути, скоплению галактик и космической паутине. Всё, что происходит
в кадре, зависит от прокрутки страницы.

**Демо:** <https://nekamita.github.io/cosmic-journey/>

**Стек:** Vite, TypeScript, Three.js (WebGL2), postprocessing (pmndrs), GSAP + ScrollTrigger, Lenis.

## Команды

```bash
npm install          # зависимости (Node.js 20.19+)
npm run textures     # скачать и подготовить текстуры (см. ниже)
npm run dev          # dev-сервер, http://localhost:5173
npm run build        # проверка типов + production-сборка в dist/
npm run preview      # раздать dist/ локально
npm test             # юнит-тесты (vitest)
npm run typecheck    # только проверка типов
```

Параметры URL для отладки:

| Параметр | Что делает |
| --- | --- |
| `?quality=low\|medium\|high` | принудительный уровень качества (без автодетекта и FPS-governor) |
| `?motion=reduced` | режим `prefers-reduced-motion` без смены настроек системы |
| `?debug` | панель lil-gui и счётчик stats-gl |
| `#saturn` (любой id главы) | открыть страницу сразу на нужной главе |

## Как это устроено

- **Один рельс камеры.** Ключевые кадры (`src/camera/cameraKeys.ts`) привязаны к якорям глав
  (`{глава, доля скролла}`), которые пересчитываются из DOM при каждом `ScrollTrigger.refresh`.
  Позиция и точка взгляда идут по двум `CatmullRomCurve3`. У ключа можно задать «остановку» (камера
  замедляется у объекта) или «пролёт».
- **Окружение по скроллу.** `src/camera/envTracks.ts` задаёт треки экспозиции, bloom, цвета фона,
  цветокоррекции, яркости звёзд, god rays, линзы, масштаба «Powers of Ten» и акцентного цвета.
- **Модули сцены.** Каждый объект живёт в своём модуле `src/scenes/*.ts` с диапазоном видимости.
  `SceneDirector` скрывает и не обновляет всё, что вне диапазона, и направляет единственный
  направленный «солнечный» свет на объект в фокусе.
- **Масштабы.** Орбиты и размеры художественные (сжатые), а цифры в тексте и счётчик расстояния
  реальные: счётчик интерполируется геометрически между настоящими расстояниями от Земли.
- **Дальний космос.** Галактика, скопление и космическая паутина живут в общей системе координат с
  центром в Стрельце A*. Отлёт от галактики к паутине сделан как «Powers of Ten»: сцена
  уменьшается, а координаты остаются в безопасном для float32 диапазоне.

Объекты и эффекты:

| Глава | Реализация |
| --- | --- |
| Земля | PBR-материал с дневной картой, normal map и маской океана (блик Солнца), ночные огни по терминатору, тени облаков, отдельный слой облаков, рэлеевская дымка и оболочка атмосферы |

| Финал | скопление галактик и космическая паутина (~120 000 точек) |

## Производительность и качество

Уровень качества выбирается автоматически (`src/config/quality.ts`): эвристика по GPU, ядрам, памяти,
`saveData` и типу устройства. Если среднее FPS долго держится ниже порога, FPS-governor понижает
уровень (обратно не повышает).

| | high | medium | low |
| --- | --- | --- | --- |
| devicePixelRatio | ≤ 2 | ≤ 1.5 | 1 |
| постобработка | полная + MSAA | без аберрации | выключена (ACES в рендерере) |
| тени (shadow map) | 2048 | 1024 | нет |
| текстуры | 4K | 2K | 2K |
| частицы | 100 % | 60 % | 30 % |

Что сделано ради скорости:

- шейдеры всех модулей компилируются под экраном загрузки;
- тяжёлые сцены дальнего космоса генерируются в idle-время уже после загрузки;
- текстуры стримятся в фоне по порядку маршрута, по одной;
- работают frustum culling, LOD планет и секторный culling астероидов;
- ячеистые шумы на low tier заменены дешёвыми.

Замеры (headless Chromium, AMD Radeon 780M, это интегрированная графика уровня среднего ноутбука):

- medium (уровень, который автодетект выбирает для этой GPU): 60 FPS во всех главах, включая
  экран HiDPI (рендер 2160×1350);
- high при DPR 2 (рендер 2880×1800): 33–60 FPS; самые тяжёлые места: Солнце, чёрная дыра,
  галактика. На такой GPU governor понизит уровень до medium;
- Lighthouse (desktop): Accessibility 100, Best Practices 100, SEO 100, Performance ≈ 63–65
  (LCP 0,6 с, CLS 0,001; TBT ≈ 1 с даёт компиляция шейдеров и загрузка текстур на GPU под
  экраном загрузки).

Цель «30+ FPS на телефоне» на реальном устройстве не проверялась: low tier и мобильная вёрстка
проверены только эмуляцией.

## Доступность и SEO

- Весь текст лежит в семантическом HTML (`<main>`, `<section aria-labelledby>`, `<h1>`/`<h2>`,
  `<dl>` для цифр) и читается без JavaScript. Canvas помечен `aria-hidden`.
- Навигация по главам состоит из обычных якорных ссылок: с JS переход идёт плавным полётом, фокус
  переносится на заголовок главы, у активного пункта стоит `aria-current`.
- `prefers-reduced-motion`: нативный скролл без Lenis, текст появляется только прозрачностью,
  автономные вращения замедлены, нет зерна, аберрации и мерцания звёзд.
- Мета-теги: description, Open Graph, Twitter Card, JSON-LD, `robots.txt`, `og-image.jpg`.

## Публикация

`npm run build` собирает статический сайт в `dist/`. Для абсолютных ссылок на превью в соцсетях
укажите адрес сайта, а для хостинга в подпути — базовый путь:

```bash
VITE_SITE_URL=https://example.com/journey
VITE_BASE=/journey/
```

Сайт публикуется на GitHub Pages workflow `.github/workflows/deploy.yml`: при каждом push в
`main` он прогоняет тесты, собирает проект с `VITE_BASE=/<имя репозитория>/` и выкладывает `dist/`.

## Текстуры

Готовые текстуры лежат в `public/textures/{4k,2k}/`, список доступных файлов хранится в
`src/config/textures.json`. Этот манифест пишет скрипт, и приложение запрашивает только те файлы,
которые в нём перечислены. Если текстуры нет, объект рисуется процедурным материалом, так что сайт
работает и без неё.

`npm run textures` делает две вещи.

### 1. Скачивает NASA (общественное достояние) автоматически

| Карта | Источник |
| --- | --- |
| Земля, дневная поверхность | [Blue Marble Next Generation, July](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/base-map/) — `world.200407.3x5400x2700.jpg` |
| Земля, ночные огни | [Black Marble 2016](https://earthobservatory.nasa.gov/features/NightLights) — `BlackMarble_2016_3km.jpg` |
| Земля, облака | [Blue Marble Clouds](https://visibleearth.nasa.gov/images/57747/blue-marble-clouds) — `cloud_combined_8192.tif` |
| Земля, рельеф (→ normal map) | [GEBCO topography](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/topography-bathymetry-maps/) — `gebco_08_rev_elev_5400x2700.jpg` |
| Земля, океаны (→ roughness, блик Солнца) | GEBCO bathymetry — `gebco_08_rev_bath_5400x2700.jpg` |
| Луна, цвет | [NASA SVS CGI Moon Kit](https://svs.gsfc.nasa.gov/4720) — `lroc_color_poles_4k.tif` |
| Луна, рельеф (→ normal map) | NASA SVS CGI Moon Kit — `ldem_16_uint.tif` |
| Марс (normal map строится из яркости) | [NASA 3D Resources](https://github.com/nasa/NASA-3D-Resources) — `Mars/Mars.jpg` |
| Ио | NASA 3D Resources — `Jupiter - Io (A)/Jupiter - Io (A).jpg` |
| Европа | NASA 3D Resources — `Jupiter - Europa/Jupiter - Europa.jpg` |

Исходники сохраняются в `textures-src/nasa/` (в git не попадают). Мозаика Европы у NASA
чёрно-белая, поэтому скрипт слегка тонирует её в бежевый цвет льда.

Карты Юпитера, Сатурна и Нептуна в NASA 3D Resources есть только в разрешении 720×360, у Ганимеда и
Каллисто в мозаиках пустые области без данных. Для них процедурные материалы выглядят лучше,
поэтому эти карты не используются.

### 2. Обрабатывает карты Solar System Scope, скачанные вручную

[Solar System Scope](https://www.solarsystemscope.com/textures/) (лицензия CC BY 4.0) закрыт капчей,
поэтому эти файлы нужно скачать в браузере и положить в `textures-src/sss/`. Подходит любое
разрешение (`2k_`, `4k_` или `8k_`): скрипт возьмёт самое большое и сам сделает версии 4K и 2K.

| Файл на сайте | Объект |
| --- | --- |
| `8k_mercury.jpg` | Меркурий (normal map строится из яркости) |
| `4k_venus_atmosphere.jpg` | облачный покров Венеры |
| `8k_mars.jpg` | Марс (normal map строится из яркости) |
| `8k_jupiter.jpg` | Юпитер |
| `8k_saturn.jpg` | Сатурн |
| `8k_saturn_ring_alpha.png` | кольца Сатурна (с альфа-каналом) |
| `2k_uranus.jpg` | Уран |
| `2k_neptune.jpg` | Нептун |

После этого запустите `npm run textures` ещё раз. Карта Марса из Solar System Scope имеет приоритет
над картой NASA, но уже собранный файл скрипт не перезаписывает. Если Марс был собран из NASA,
запустите `npm run textures -- --rebuild`.

Ключи скрипта: `--offline` (ничего не качать), `--rebuild` (пересобрать выходные файлы),
`--force` (перекачать NASA и пересобрать всё).

Солнце, Ганимед и Каллисто, астероиды, кометы, чёрная дыра, галактики и космическая паутина
процедурные (GLSL), текстуры для них не нужны.

## Структура

```text
index.html                  семантическая разметка всех 13 глав, SEO-мета
scripts/fetch-textures.mjs  пайплайн текстур (sharp)
src/
  main.ts                   сборка приложения и кадровый цикл
  config/                   главы, компоновка сцены, реальные расстояния, уровни качества
  camera/                   якоря глав, keyframe-треки, рельс камеры, параметры окружения
  core/                     renderer, постобработка, ассеты
  scroll/                   Lenis + ScrollTrigger, прогресс полёта
  scenes/                   по модулю на объект + SceneDirector
  shaders/                  GLSL (общий шум, звёзды, Солнце, атмосферы, диск, галактика…)
  ui/                       появление текста, навигация, счётчик расстояния, загрузчик
  styles/main.css
```
